# Putting Femalogy online (Render + Neon, EU)

About 20 minutes. You need a GitHub, Neon and Render account. Use the same email for all three, and turn on 2FA on each.

## 1. Database: Neon (Frankfurt)

1. Sign up at neon.tech (signing in with GitHub is fine).
2. **Create project:** name `femalogy`, Postgres version **16**, region **AWS Europe Central 1 (Frankfurt)**.
3. On the project dashboard, click **Connect** and copy the connection string. It looks like
   `postgresql://user:password@ep-...eu-central-1.aws.neon.tech/neondb?sslmode=require`.
   This is a password. Only paste it into Render, nowhere else.

## 2. Make the notes encryption key (on your Mac)

```bash
cd ~/Documents/femalogy/femalogy-backend
.venv/bin/python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

- Make a **new** key for production. Don't reuse the one in your local `.env`.
- Save it in a password manager. If it's lost, users' notes can't be read again. Don't put it in the repo, a file or a chat.

## 3. App: Render (Frankfurt)

1. Sign up at render.com with GitHub and let it see the `femalogy` repo.
2. **New → Blueprint** → pick `mdkbk/femalogy`. Render reads `render.yaml`.
3. It asks for two values:
   - `DATABASE_URL`: the Neon connection string from step 1.
   - `FIELD_ENCRYPTION_KEY`: the key from step 2.
   `SECRET_KEY` is generated by Render automatically.
4. **Apply.** The first build takes about 5 to 10 minutes. It builds the web app, installs the API, and runs the database migrations on start.
5. Your address is shown at the top, something like `https://femalogy.onrender.com`. Share that link.

## 4. Check it

- `https://<your-address>/api/health` should show `{"status":"ok"}`.
- Open the address, create an account, log a period and do a check-in.
- Account menu → **Download my data** should give you a file with exactly what you entered.

## After that

- **Updates:** every `git push` to `main` redeploys automatically.
- **Free plan:** the app sleeps after about 15 minutes idle, so the next visit takes around 30 to 60 seconds to wake. Switch the service to **Starter** in Render when real users arrive.
- **Logs:** Render → femalogy → Logs. They don't contain passwords, tokens or notes.
- **If a secret leaks:**
  - `SECRET_KEY`: change it in Render and redeploy. This only affects login rate-limit records.
  - Neon password: reset it in Neon, then update `DATABASE_URL` in Render.
  - `FIELD_ENCRYPTION_KEY`: rotating it needs a small migration that re-encrypts the notes. Ask before changing it, because changing it on its own makes existing notes unreadable.
- **Custom domain** (later): Render → Settings → Custom Domains. HTTPS is automatic.
